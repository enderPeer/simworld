# SimWorld website

The public project site is [enderpeer.github.io/simworld](https://enderpeer.github.io/simworld/).
GitHub Pages serves its static files independently of a development computer.
The repository's Pages workflow builds and validates the site before deployment.

## Edit and preview

The site uses plain HTML, CSS and JavaScript. No package installation or framework
build is needed. From the repository root:

```sh
python website/build_content.py
python website/check_site.py
node website/server.mjs
```

Open <http://127.0.0.1:8787/>. Stop the local server with Ctrl+C. The Node server
serves only `website/dist/`; project files and local runtime logs are not exposed.
You can also serve that directory with another static HTTP server.

| File or directory | Purpose |
| --- | --- |
| `dist/index.html` | Main page, navigation and accessible structure |
| `dist/styles.css` | Desktop and mobile layout |
| `dist/app.js` | Phase explorer, document search, reader and download controls |
| `build_content.py` | Generates current project data, documentation copies and archives |
| `check_site.py` | Checks publication paths, downloads and metadata before deployment |
| `dist/data/` | Generated project metadata and download checksums |
| `dist/docs/` | Generated copies of phase plans and specifications |
| `dist/downloads/` | Published paper, source packages and audit evidence |

Asset paths are resolved relative to the HTML document. The same output works at
the root of a local server and under GitHub's `/simworld/` project path. Keep
links inside the site relative; external research and repository links use
complete HTTPS URLs.

## Source documents and archived evidence

Edit the original `ROADMAP.md`, `BUILD0.md`, `PHASE*.md` and `spec/` files in the
repository, then run the content builder. Do not edit their generated copies in
`dist/docs/`. Available detailed phase plans are detected from those source
files. A plan's presence does not imply that its mechanism is implemented.

The paper and archive are committed publication inputs, not generated by the website build:

- `dist/downloads/SimWorld_Research_White_Paper.pdf`
- `dist/downloads/SimWorld_Research_Materials_Public.zip`
- `../research/whitepaper/publication.json` records the version, page count, source baseline, and PDF checksum.

Version 1.1 covers all seventeen detailed phase plans and the verified public project status. The archive separates its current source baseline from the original audit source and measurements. The builder reads the
public research ZIP to obtain the original results, test report and literature
metadata. It does not require local `tmp/` or `output/` directories and does not
rerun the physics audit. Replacing either input is an explicit research-publication
change and should explain the new evidence in its commit.

Editable manuscript, phase profiles and rendering/package tools are tracked in
`research/whitepaper/`. See that directory's README for revising the paper. The
website validates its publication metadata instead of keeping a separate hardcoded
page count or version label. Versioned PDF/archive download URLs avoid reusing an
older cached file after a publication update.

Current engine-source and documentation ZIPs are rebuilt from allowlisted source
files, with fixed archive ordering and timestamps. Download metadata records the
size and SHA-256 of the actual distributed bytes. Workstation identifiers are
removed from public distributions. The current-source archive is intended for
running the engine; clone the full repository to work on the website tooling.

## Publishing

Push the reviewed change to the repository's publishing branch. The GitHub Pages
workflow builds the content, validates it, and uploads `website/dist/` as the
deployment artifact. Check the workflow result before considering the new
version live. Historical audit results remain labeled as historical rather than
being presented as a fresh test run each time the website deploys.

For a temporary Cloudflare preview, the existing Windows `start.ps1` and
`stop.ps1` scripts remain available. Their usage is documented in `README.txt`.
That tunnel is optional and is not involved in GitHub Pages hosting.
